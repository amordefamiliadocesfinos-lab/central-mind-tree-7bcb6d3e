## 1. Resultado comprovado e fronteira de identidade
A01–A06: piloto documental, persistência, replay e recuperação em novo chat.
A07.1–A07.5: AC-01, FM, M3, M4 implantados; delta SHO concluído no recorte documental.

GitHub é fonte de código, decisões e documentos versionados. Lovable Cloud é Core de registros e histórico. O canal proprietário Lovable chega ao banco como postgres, sem UID Auth individual; os quatro escritores são privados, SECURITY INVOKER, sem USAGE/EXECUTE para anon, authenticated e service_role. Verificar vínculo owner, projeto/repositório oficiais e autorização do ato antes de executar. Origem administrativo_lovable identifica o canal, não identifica individualmente o especialista. A referência de decisão é metadado verificável pelo chamador, não assinatura ou autenticação automática da autoridade pelo banco. Não há proteção contra superusuário deliberadamente malicioso. Não compartilhar credenciais, simular JWT/auth.uid, usar INSERT/UPDATE avulso de conteúdo, ampliar grants ou expor endpoints. Escritores humanos permanecem preservados.

## 2. Contratos efetivos (schema nucleo_u06f_private)
AC-01: register_ac01_proposal(p_request uuid, p_module uuid, p_workstream uuid, p_role text, p_kind text, p_title text, p_locator text, p_note text, p_decision text). Proposta inicial V1, módulo e frente existentes (frente opcional, se informada pertence ao módulo), fonte GitHub oficial em commit SHA completo e docs/ permitido, referência de decisão em comentário de issue. Não alterar/prometer revisão de lineage administrativa ou promoção/publicação; revisão de linhagem exige contrato próprio. Não duplicar referência já registrada no módulo; reconciliar antes. A versão do documento não é a versão do registro.
FM: register_fm_revision(p_request uuid, p_module uuid, p_section text, p_expected_version integer, p_title text, p_body text, p_source text, p_decision text). Nova revisão append-only de seção existente FM-01–FM-10, expected_version >=1, versão atual exata, conteúdo e referências históricas reconciliados, autoridade rascunho, evidência declarado, reviewed_by vazio. A hipótese de seção inédita com versão 0 da candidata NÃO foi implantada. Não editar revisões anteriores.
M3: register_m3_checkpoint(p_request uuid, p_workstream uuid, p_expected_updated_at timestamptz, p_expected_before text, p_checkpoint text, p_action text, p_decision text). Registro existente, CAS de timestamp e texto integral; preserva texto anterior convertendo marcadores históricos, acrescenta checkpoint e ação, evento oficial com before/after e request. Não alterar situação, evidência, responsável, dependências ou estrutura de frentes; delta somente next_action e metadados updated_at/updated_by_auth_uid. Não inserir marcadores de ação vigente/próxima ação nos argumentos de checkpoint e ação. Replay antigo retorna evento original sem restaurar estado posterior.
M4: register_m4_observation(p_request uuid, p_workstream uuid, p_source text, p_kind text, p_key text, p_title text, p_note text, p_decision text). Observação append-only em registro existente, GitHub oficial pull_request/workflow_run/commit com chave e URL derivada, ou migration Supabase com versão de 14 dígitos presente no ledger. observed_state observado, checked_at nulo, snapshot vazio, nenhum efeito em M3. Não certificar verificado/homologado, execução, deploy ou operação por inferência. Verificação externa deve ser realizada na origem e descrita na nota com limites. Não repetir referência na mesma frente. 
Todos: request UUID único por ato, payload estável, origem administrativo_lovable, UID humano nulo. Reenvio exato retorna confirmado_existente e mesmo identificador; primeiro ato retorna confirmado_por_readback. Conflito de request/referência ou CAS obsoleto bloqueia, não reescrever história. Legado não classificado não recebe autoria retroativa.

## 3. Jornada mínima de uso
1. Assumir a especialidade recuperando Core e GitHub, identidade funcional, método, mapa, escopo, autoridade, últimas revisões, próxima ação e evidências. O conector administrativo é caminho operacional Nível 3, separado de AC-02 autenticado na aplicação.
2. Reconciliar fontes atuais, identificar somente delta material autorizado. Não duplicar documento existente, reabrir etapa concluída, assumir vigência operacional a partir de um relato antigo nem substituir decisão competente.
3. Conferir owner/projeto, módulo/frente/versão e existência real da fonte imutável e decisão; registrar nota de autoridade e limites. Obter UUID novo por ato e conservar argumentos exatos, sem incluir segredos ou dados privados desnecessários.
4. Invocar somente função oficial apropriada pelo conector Lovable Cloud (SELECT da função é ato de escrita, não leitura). Agrupar atos compatíveis numa transação se todos forem autorizados e o escopo for único; usar CAS, lock timeout e rollback em divergência. Não modificar schema para cada documento.
5. Realizar SELECT independente do registro persistido, estado de autoridade, origem, referência e identidade da requisição. Conferir delta esperado, histórico e ausência de efeitos colaterais. Em transporte incerto, consultar por request antes de repetir; reenvio idêntico é seguro no contrato comprovado, não gerar outro UUID para contornar conflito. Falha sem confirmação exige reconciliação, não alegar sucesso.
6. Registrar checkpoint/resultado no GitHub e, se autorizado, no próprio Núcleo pelo escritor correspondente; não duplicar referência ou registro já existente. Novo chat recebe apenas comando de assunção, recupera evidências do Core/GitHub e identifica próxima ação sem depender de repasse manual.
7. Para engenharia futura, não reconstruir capacidade existente: migration versionada GitHub, CI descartável e integrada, merge, compatibilidade publicada antes de schema incompatível, aplicação transacional do arquivo exato com pre/postflight e registro no ledger Supabase na mesma transação. A trilha nativa Drizzle apresentou divergências antigas; não reparar por inferência. A trilha chatgpt_git_direct já documentada foi comprovada. Sem alterações produtivas de código, schema ou grants por rotina documental.
